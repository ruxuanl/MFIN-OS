# 安全模型：M0-M7 与岗位发现 V0 规划边界

本文件只定义工程治理底线，不替代后续权限、数据分类、威胁模型和恢复设计。

## 数据与凭据边界

- 仓库不得包含 OAuth 令牌、密码、验证码、服务角色密钥、私钥或真实账号数据。
- `.env.example` 只保存空占位符；真实 `.env*` 被 Git 忽略。
- Supabase service role、Google client secret、AI key 等服务端凭据不得进入浏览器包。
- Gmail/Calendar 长期令牌未来只保存在受控服务端密钥存储，不进入普通业务字段。
- 日志、审计、报告和测试失败输出不得包含完整邮件、材料、微信聊天或凭据。

## 测试数据

- 仓库只允许合成或不可逆匿名化夹具。
- 真实简历、课程文件、邮件、微信截图和日历内容不得提交。
- 真实联调使用专用测试账号；每个连接必须有撤销和删除路径。

## 自动化安全门

- 权限中心必须在服务端执行路径生效。
- 任务开始和外部写入前重新检查权限；关闭后取消队列并在安全点停止。
- 永久禁止的发送、联系、投递和申请提交能力不得出现在能力注册表中。
- 第二阶段浏览器自动化和凭据保险库不得提前实现；Windows 微信监测仅能在已批准的 M7 白名单/本地净化边界内建设。

## 供应链与仓库

- 依赖使用锁文件固定；M0 暂无第三方运行依赖。
- CI 采用最小只读权限。
- `main` 保存已验收里程碑；工作分支使用 `codex/` 前缀。
- 发现疑似密钥时停止提交，先撤销/轮换，再清理历史；不得仅删除当前文件后继续使用旧密钥。

## M2 权限与任务强制执行

- `public` schema 的每张表显式启用 RLS；`anon` 无表权限，`authenticated` 只有完成页面功能所需的最小权限。
- AI 行为同时要求 AI 总开关和细项授权；隐私锁优先于所有授权与连接状态。
- 隐私锁启用后排队任务立即取消，运行任务进入 `cancel_requested`，新的外部读取、AI、同步、上传和任务创建由数据库阻止。
- 解除隐私锁要求 JWT `amr` 中存在晚于锁定时间的新认证方法；普通 token refresh 不算重新验证。
- 仅本次授权绑定 `operation_id`，任务终止后自动消费；限时授权使用服务器绝对时间，过期后判定立即失效。
- 审计、撤销和任务 JSON 递归拒绝敏感字段名，并限制载荷大小；普通日志只允许引用、错误码和必要摘要。
- 内部 `SECURITY DEFINER` 触发器位于未暴露的 `private` schema，锁定空 `search_path`、固定写入形状并撤销客户端执行权限。
- 私有密钥引用表不保存密钥值，启用 RLS 且没有客户端策略；实际密钥继续由托管服务端密钥系统承载。

## M3 工作区与离线安全

- M3 业务表全部启用 RLS；`anon` 无表权限，`authenticated` 只获得显式的 SELECT/INSERT/UPDATE/DELETE 或指定 RPC 权限。
- 读策略与写命令策略分离；写入继续调用仅返回布尔值的窄私有隐私锁判定函数，客户端不能读取私有表或密钥引用。
- promotion、并发 mutation 与冲突解决 RPC 使用 invoker 权限并再次核对 `auth.uid()`、隐私锁、对象所有权和允许字段。
- 所有者、岗位轨道和上下文身份由触发器保持不可变；客户端不能通过普通 UPDATE 绕过领域边界。
- Outbox 和快照不得存放令牌、验证码、完整邮件/材料正文或证据原文；Service Worker 不缓存认证 API 响应。
- 自定义字段、时间线和同步载荷沿用递归敏感键拒绝与大小限制；冲突记录只保存解决所需字段值。
- mutation ID 防止重放造成重复副作用；字段级基线比较阻止离线客户端静默覆盖另一端的新值。
- 实习 JD 入口只接受用户主动粘贴的 20–50000 字文本；浏览器显示规则预览，服务端重新解析并验证公司、岗位、JD 发布时间、截止日期、HTTPS URL 和状态白名单。远程/混合办公只作为地点文本的一部分保存。
- 原始 JD 只进入对应正式岗位字段，不写入普通日志、审计 before/after 或错误信息；审计只保存指纹、解析版本、置信度、缺口与阶段。
- `import_my_internship_jd` 使用 `SECURITY INVOKER` 与现有 owner RLS/隐私锁谓词；匿名角色无执行权。相同指纹使用唯一索引和事务锁防止重复。
- 用户选择“已投递”只设置产品内阶段和投递时间；数据库函数没有网络、消息、联系或申请提交能力。

## 简历与 OpenAI 分析边界

- 只有用户当前选择的一条 JD 与一个简历版本可进入一次分析；不得附带邮箱、日历、微信、其他岗位、其他简历或无关账户数据。
- OpenAI 请求由服务器发起，使用 `store=false`、结构化输出和有界输出长度；API key、模型与实时价格配置仅存在于服务器环境，不进入浏览器、数据库、普通日志或仓库。
- 简历上传先按文件字节验证真实 PDF/DOCX 类型、10 MB 上限、页数/压缩包边界、加密状态和可抽取文本；拒绝伪装、扫描版、空白或异常压缩文件。
- `resume-files` 永久为私有桶。数据库版本元数据只有在目标对象已存在且属于当前用户路径时才能登记；浏览器打开文件前重新通过 owner RLS，并只签发 60 秒下载链接。
- Master 与派生简历版本均不可原位覆盖。岗位表保存精确版本引用；没有针对性修改时只显式回退到最新 Master，避免把通用版误标为专用版。
- 数据库在任何供应商调用前按香港自然月加锁预留成本；已完成与在途预留达到 HK$100 时拒绝请求。供应商侧预算仍作为第二层保护，不替代数据库硬门。
- AI 输出仅为凝练、可解释评分、缺口、紧急度、修改建议和可编辑邮件正文草稿；系统没有发送邮件、联系招聘方、提交申请或改写/覆盖简历文件的动作。

## M4 Calendar 安全

- Calendar 独立 OAuth 只申请日历清单只读、事件只读和“本应用创建的日历”权限；不申请 Gmail、ACL 或全账户日历写权限。
- OAuth 使用随机 state、S256 PKCE、十分钟 HttpOnly/SameSite cookie；连接和断开要求新鲜再验证。回调失败不记录授权码、令牌或 client secret。
- access/refresh token 只存 Supabase Vault；Vault 和增量游标 RPC 仅授予 service role。浏览器只能看到连接状态与非敏感错误码。
- 其他测试日历始终只读；更新前同时核对产品日历、Google 私有产品标记、目标 Action ID 和 ETag。无法证明所有权时进入 `write_protected` 冲突，不发送请求。
- 远端删除和 412 并发变化进入显式冲突；不自动重建、不删除 Action、不静默覆盖。410 只重建本地镜像与游标。
- 权限关闭只保留待同步操作；连接暂停、断连、令牌失效或隐私锁会在外部读取/写入前安全停止。断连先尝试远端撤销，再删除 Vault 凭据；撤销未确认会明确提示用户复核 Google 账号。
- Calendar 表对登录用户保持只读。外部可见 RPC 是 invoker 薄包装；高权限实现位于未暴露的 `private` schema，固定空 `search_path`，仍逐项核对 `auth.uid()`、隐私锁和对象所有权。

## M5 报告与通知安全

- 报告生成在开始时复核 `reports.generate`、隐私锁和用户身份；调度任务带幂等键、安全检查点、有限错误状态和行锁，且不执行网络 I/O。
- 报告/条目对客户端只读并保留不可变版本。客户端不能写调度运行状态，只能经私有 definer + 公共 invoker 的窄 RPC 修改本人日程的 `enabled` 和 `local_time`。
- 通知入队复核 `notifications.smart_push`，类型受数据库白名单约束并以 `(user_id, dedupe_key)` 去重；客户端不能伪造投递状态，只能设置本人的 `read_at`。
- 晚间收口必须由用户显式提交允许的结果；改期必须有时间，并追加审计/时间线。系统没有自动滚动未完成项，也没有未经确认的 Calendar 写入。
- D07/D08 未确认，`rules_v1` 不调用 AI，不传出报告数据，也不标注为 AI 推荐。

## M6 Gmail 安全

- Gmail 独立 OAuth 只接受精确 `https://www.googleapis.com/auth/gmail.readonly`；scope 增加即拒绝。适配器只有 GET，不实现发送、回复、草稿、归档、删除、标签或已读变更。
- OAuth 使用 state、S256 PKCE、HttpOnly/SameSite cookie 和 offline consent；令牌只进入 Vault，回调与错误不记录授权码或令牌。
- 每次 Gmail 外部请求前重新计算权限；暂停、断连、隐私锁或授权失效立即停止新读取。断连尝试远端撤销并删除 Vault 凭据。
- 完整正文只在单次内存投影中短暂存在；普通表只保存最小摘要、证据摘录、哈希和 Gmail 链接，个人邮件进一步收缩为行动与日期。
- Gmail 公共表对客户端只读；投影与自动更新 RPC 仅 service role 可执行。附件桶为私有且无浏览器写策略。
- 高置信更新必须是规则版 `mail_rules_v1`、唯一岗位匹配且可撤销；低置信内容进入待确认，不静默改表。

## M7 Windows 微信监测安全门（数据库与控制面切片已实施）

- 仅监测用户逐项确认的白名单招聘群；白名单身份必须稳定核对，不能仅靠窗口位置或模糊标题猜测。
- 只使用用户已登录的微信桌面端可见界面和本地视觉/OCR；禁止索取密码、导出本地数据库、注入/Hook 客户端、绕过安全机制或调用发送能力。
- 原始截图仅在本机受控临时目录短暂存在，完成过滤、裁剪、去标识和投影后删除；非 JD、非白名单内容及完整聊天不得上传或长期保存。
- 云端只保存岗位字段、群来源、时间、必要证据片段、内容哈希、采集版本和置信度；发送者信息仅在证明岗位来源确有必要时最小化保留。
- 必须有总开关、逐群开关、暂停、立即停止、低频速率限制、幂等游标和可见心跳；权限关闭、隐私锁、锁屏、微信退出、UI 不确定或账号异常时 fail closed。
- 永久禁止发送/回复微信、添加联系人、点击投递、读取验证码或自动申请。监测器不得把“未运行”冒充“今日无新岗位”。
- 数据库切片已用 `wechat.monitor` 及依赖授权、稳定群身份哈希、新鲜心跳和 stop generation 在 service-only 原子入口中 fail closed；浏览器只能通过最小授权 RPC 配置自己的哈希白名单与期望状态，不能直接写表。
- 特权控制与心跳实现位于不暴露的 `private` schema；公开 RPC 是 `SECURITY INVOKER` 薄包装。暂停、停止和逐群禁用原子递增停止代数，并取消排队任务或请求运行任务在安全点停止。
- 本地循环在扫描前、逐群和每个投影写入前重新读取任务分配并上报新鲜心跳；服务端拒绝旧停止代数、权限/隐私锁失效、空白名单和未知适配器。`visible_ocr_v1` 心跳必须同时证明 Windows Media OCR、只点击可见列表、键盘/剪贴板/发送能力均为 false，字段缺失也会被拒绝。
- 微信 4.1.12.55 适配器只使用 `PrintWindow`、本机 OCR 和受坐标约束的鼠标左键；当前群无需点击。切群要求用户空闲、微信前台、目标群在可见列表、标题哈希唯一，且导航至少间隔 90 秒；不自动滚动。中央区域出现账号/登录/验证风险词会在任何点击前停止。
- PowerShell 5.1 帮助进程将标准输出固定为 UTF-8 无 BOM；Node 仅接收单帧 OCR 结果并在本地归一化汉字间空格。邮箱、手机号或微信号会先在去空格文本上识别，命中后整行替换为类别标记，避免 OCR 插入空格绕过净化；聚合诊断只输出行数、字符数、信号计数和置信度，不输出原文。
- 群配对由 service-only public invoker/private definer 边界写入默认关闭的白名单行，并记录无发送能力声明；真实目标群在用户明确授权后以 24 小时临时权限启用。当前身份由可见标题派生，标题变化或同名群会停止并要求重新核对，不能猜测；不声称取得微信内部稳定群 ID。
- Windows 登录任务直接托管 Node Worker，保证计划任务停止时 Worker 同步终止；结构化本地日志不得包含 OCR 原文、群名、身份指纹或密钥。数据库心跳仍是运行健康的权威来源。
- 自动监测截图只写入用户临时目录下固定名称的专用根目录；正常路径完成 OCR 后立即删除。异常中断残留最长保留 5 分钟，每次 helper 启动/探测都会清理；清扫只允许删除专用根目录下严格匹配 `capture-` 加 32 位十六进制名称的直接子目录，并在递归删除前复核规范化父路径，不能触及其他临时文件。
- 手动兜底只接受用户主动提交的文字或 HTTPS 链接、结构化岗位字段和最长 1000 字必要证据；不访问链接、不表示完整聊天。入口重新检查 `wechat.import` 及本地净化依赖，重复投影幂等，未核对内容停在待确认。
- 手动截图只允许 PNG/JPEG/WebP 且最大 5 MB；先按文件字节核验类型，在随机、权限收窄的 OS 临时目录计算哈希，并在任何成功记录前递归删除该专用目录。数据库只保存哈希/MIME/大小/删除事实和 `ocr_unavailable`；记录 RPC 仅 service role 可执行并复核 `wechat.import`、`files.upload` 与隐私锁，浏览器不能伪造删除证明，不保存原文件名、路径或图像。
- 手动文件只允许 PDF/DOCX/XLSX 且最大 5 MB；PDF 最多 40 页，Office 压缩包限制条目数、单个/总 XML 解压大小和工作表数，并拒绝加密、路径穿越、类型伪装与超时。只在可信 Web 请求内提取最多 20000 字并输出最长 1000 字的已净化证据；原文件、文件名和完整文本不入库，扫描版/纯图片 PDF 返回 `ocr_unavailable`。写入 RPC 仅 service role 可执行，原子复核 `wechat.import`、`files.upload`、本地净化依赖与隐私锁，且强制 pending、禁止自动进入候选池。

## 岗位发现 V0 公开来源安全门

- 只允许无需登录的公开 HTTPS 来源；来源域名、覆盖范围、使用说明、适配器版本和最低间隔必须先登记。
- 来源建议默认待审批且关闭。用户批准不会启动采集；显式启用时数据库再次检查 `job_radar.discovery` 与隐私锁。
- 客户端只能读取本人来源和运行健康；不能直接创建来源、伪造运行结果、写游标或写候选。服务端运行 RPC 仅 service role 可执行。
- 运行键按来源幂等；低于声明间隔的新运行被拒绝。部分/失败必须保留覆盖缺口，权限失效后的成功提交会被改记为安全取消。
- 当前切片不访问真实网站，不包含受限平台登录、账号凭据、联系、发送、收藏、投递或申请提交，也不自动创建候选。

## 投递包边界（#13）

- 投递包只在产品内准备材料：不打开、填写或提交任何招聘平台表单，不登录，不发送邮件，不联系任何人；官方链接只在新标签页打开，由用户本人提交。
- 简历推荐只是建议；“最终申请材料”由用户点击确认后写入（宪法 4.5）。
- 状态不能在此流程中置为 `submitted_recorded`；浏览器角色对两张表没有 insert/update/delete 权限；隐私锁开启时全部写入被服务器拒绝。长期测试固定以上边界。

## 投递记录边界（#14）

- “我已投递”只记录用户已在官网完成的事实，不访问任何外部系统；审计中固定 `externalAction: false`。
- 浏览器角色对 `application_snapshots` 只读；快照即使由数据库所有者也无法改写内容（触发器拒绝），只允许一次撤销标记。
