# ADR-0009：求职方向增强（精简版）

- 状态：已接受（2026-11-12，用户确认按推荐默认执行）
- 日期：2026-11-11，2026-11-12 精简
- 对应决策：D07、D08、D09、D23、D25、D28–D34
- 执行方式：按 `docs/SCRUM.md` 的周 Sprint 推进，任务以 GitHub Issues 为准

## 1. 目标

在用户自有的隔离 Test 环境中，先跑通求职主链路的基础闭环，再逐步增强：

> 登录 → JD 建档（实习/秋招）→ 投递包 → 用户在官网提交 → “我已投递”与申请快照 → 统一搜索

四个方向的优先级：检索增强、投递准备自动化（到提交之前）、工作流优化、响应速度。

## 2. 现状要点

| 方面 | 现状 | 影响 |
|---|---|---|
| 搜索 | `/search` 是占位页；数据库没有任何检索扩展或索引 | 检索需从零建设 |
| 列表 | `select("*")` 取回全部行（含 ≤5 万字符的 `raw_jd`），在 Node 端过滤排序，无分页 | 列表慢、载荷大 |
| mock 模式 | 所有数据函数返回空数组 | 不能用于功能、检索、性能验证，必须接 Test 环境 |
| JD 建档 | 只有实习页有粘贴入口 | 秋招需手动录入 |
| 投递 | 只改阶段字段，没有申请快照、材料清单、官方链接 | 无法回溯“当时投了什么” |
| 关联 | 公司、技能只是文本；`gmail_updates` 只记录自动应用的面试邀请 | 回答不了“哪些岗位还没回复” |
| 简历 | 只存抽取字数，不存文本 | D30 后新增私有文本存储 |
| AI | 只有 `resume`、`jd_match` 两类调用，受 HK$100/月硬预算约束 | 新用途需新迁移 |
| 退役功能 | 收件箱每次加载仍查询微信历史表 | 改为按需加载，数据保留 |

## 3. 约束（不变的红线）

- **不自动投递**：不自动填表、不提交申请、不登录招聘平台、不读验证码、不发送邮件。投递包只准备材料，提交由用户在官网完成，“我已投递”只记录事实。
- **最终材料由用户选择**：系统推荐简历版本，用户确认后才写入。
- **AI 数据范围**：每次只发送一条 JD、一个用户确认的简历版本，以及用户粘贴的申请问题；邮件、日历、报告不发给任何外部 AI 或嵌入服务。
- **检索**：经过 owner RLS；隐私锁开启时服务器拒绝；结果带来源和时间；完整邮件正文不进索引。
- **来源**：新官网适配器只在 Test 实现，保持 `approved / disabled`；每日自动搜岗仍暂停，启用需用户另行命令。
- **Calendar**：用户保存的截止日作为明确事实进入队列；建议的准备时间块必须经用户确认。
- **环境**：只用本地与隔离 Test、合成数据；迁移只新增；不提交密钥或真实数据；不碰 Production。

## 4. 设计要点

- **检索（D09）**：新增可重建的 `search_documents` 投影表，由 `private` 触发器增量维护；中文用 PGroonga（不可用时退回 `pg_trgm`），英文用 `tsvector`；与结构化过滤一起用倒数排名融合（k = 60）。向量检索暂不做（D28）。
- **关系层（D34）**：`companies`、规则词典 `skills_dict_v1`、`opportunity_skills`、`resume_version_skills`、`opportunity_communications`（邮件与岗位的通用关联）。多跳问题用预置 SQL 模板实现，不引入图数据库或 KAG。
- **升级到 KAG 的条件**（满足任意两条再立项）：多跳问题准确率低于 80% 且原因是表达能力不足；关系类型超过约 15 种；需要自然语言直接生成多跳查询；节点规模达到 10⁵ 量级。
- **投递包**：状态 `draft → ready → submitted_recorded / abandoned`；规则版负责简历推荐（技能重叠）、材料清单、截止 Action、官方链接；AI 版（D29）负责求职信、申请问答和差距解释，编辑后字段锁定。
- **申请快照**：“我已投递”写入不可变快照（JD 原文、简历版本、问答终稿、申请编号），追加时间线和审计，可撤销。
- **性能**：先计时再优化；列裁剪、数据库侧筛选分页、`requireUser` 请求内去重、退役查询按需加载、`Suspense` 分块；首要指标是减少数据库往返批次（数据库在新加坡）。

## 5. 数据模型变更（全部新增迁移）

| 迁移 | 内容 |
|---|---|
| `search_documents_v1` | 检索扩展、投影表、触发器、重建函数、`search_my_workspace` RPC |
| `job_relations_v1` | 公司、技能关联、邮件与岗位关联 |
| `resume_text_v1` | 简历抽取文本私有表（随版本永久删除） |
| `application_packages_v1` | 投递包、材料清单、不可变申请快照、“我已投递”RPC |
| `ai_application_drafts_v1` | `analysis_kind` 增加 `application_pack`，可编辑草稿 |
| `workflow_batch_v1` | 候选批量处理 RPC |
| `perf_indexes_v1` | 按实测补的索引 |

## 7. AI 成本

按每月约 40 次岗位匹配和 30 次投递包生成估算，合计约输入 0.4M、输出 0.14M tokens。月成本（美元）≈ 0.4 × P_in + 0.14 × P_out（P 为每百万 tokens 单价）。以示例单价 2.5 / 10 计算约 US$2.4（约 HK$19），单价翻倍约 HK$38，都在 HK$100 预算内。配置前必须按 OpenAI 官方价格核对（D08）；投递包输出较长，需相应调高单次预留值。
