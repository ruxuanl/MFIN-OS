# ADR-0002：M2 PostgreSQL 权限与任务底座

- 状态：已接受
- 日期：2026-08-10
- 对应决策或里程碑：D03、D04、D17；M2

## 背景

M2 需要持久化权限、隐私锁、审计、撤销和可取消任务，但真正的定时采集、AI、Gmail 与 Calendar Worker 尚未进入获批里程碑。此时锁定额外队列供应商会增加成本和迁移负担。

## 决定

- 使用现有新加坡 Supabase PostgreSQL 作为 M2 持久化任务状态与失败队列底座。
- 任务通过幂等键、状态机、权限快照、安全点、有限重试和 `dead_letter` 表达；M2 不运行定时 Worker。
- 权限、隐私锁和任务取消在数据库触发器与 RLS 中强制执行，UI 只展示和发起受限操作。
- 客户端只使用 publishable key；`service_role`、OAuth 令牌和其他密钥不进入浏览器或普通业务表。
- 未来需要定时自动化时，再独立选择 Worker/调度运行时；当前表结构作为供应商无关契约保留。

## 后果

- M2 可在不增加付费服务和真实数据的情况下完成端到端安全验证。
- 任务执行器仍是后续里程碑工作；当前状态中心不会伪装为已有后台采集。
- 权限变更、隐私锁和一次性授权消费可以在 Worker 尚不存在时先被可靠测试。

## 验证

- 真实 PostgreSQL 事务验证 AI 总开关、隐私锁、权限到期/撤销、一次性授权、重试上限、dead-letter、敏感载荷拒绝和永久禁止能力。
- Supabase Security Advisor 没有公开 schema 的 RLS 或函数暴露告警；私有密钥引用表保持 RLS 且无客户端策略。
