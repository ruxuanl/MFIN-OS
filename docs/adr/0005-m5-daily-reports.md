# ADR-0005：M5 今日行动与规则报告

- 状态：Accepted
- 日期：2026-08-13
- 决策来源：用户批准从 M4 检查点继续建设；`docs/PRODUCT_SPEC.md` 与 `docs/IMPLEMENTATION_PLAN.md` 的 M5 范围

## 背景

M5 需要每日首页、晨报、晚间收口、周报和智能通知，但 D07/D08 的 AI 供应商与预算尚未确认。系统必须提供可用闭环，同时不得把确定性规则伪装成 AI，也不得让报告成为新的事实源。

## 决策

1. PostgreSQL/Action 仍是行动事实源；报告是带截止点、来源健康和策略版本的不可变快照。
2. 当前重点排序采用 `rules_v1`：按优先级、截止和资格/匹配分数排序，首页最多三项，每条求职线最多五项；界面明确标注“非 AI”。
3. 三类日程由 `pg_cron` 每五分钟扫描到期项；生成前复核权限与隐私锁，使用幂等键、事务 advisory lock、`SKIP LOCKED` 和明确失败状态。
4. 晚间未完成项不自动顺延；用户必须显式选择继续、等待、取消、降级或改期，结果追加审计和时间线。
5. 智能通知以数据库白名单和用户级去重键约束。客户端只读系统状态；配置写入通过公共 invoker 包装私有 definer。

## 后果

- 即使 AI、Gmail、微信和岗位雷达尚未连接，M5 仍可基于现有可信数据工作，并显式展示来源缺口。
- 未来确认 D07/D08 后可增加新的策略版本，但不能覆盖历史报告，也不能未经确认把建议时间块写入 Calendar。
- SQL 调度当前不承担 Web Push 网络投递；通知表提供安全队列和状态边界，后续投递器仍须遵守相同白名单、权限和去重规则。
