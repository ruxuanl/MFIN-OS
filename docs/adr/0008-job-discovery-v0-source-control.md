# ADR-0008：岗位发现 V0 公开来源控制面

- 状态：Accepted
- 日期：2026-08-25
- 决策来源：用户已授权在 Production、Calendar、日报后推进岗位发现 V0；`PRODUCT_SPEC.md` 的审批、只读、覆盖诚实与禁止投递边界

## 背景

D14-D16 的岗位画像、硬条件与初始来源清单尚未由用户确认，因此系统不能替用户选择公司或招聘平台，也不能直接启动真实抓取。但后续公开来源需要统一的审批、频率、权限、健康和覆盖缺口契约，避免每个适配器自行扩大范围。

## 决定

1. 每个来源必须声明公开 HTTPS 域名、覆盖范围、适配器版本和 60 分钟至 7 天的最小采集间隔。
2. 系统只能提出默认关闭的来源；用户批准后仍保持关闭，显式启用时再次检查 `job_radar.discovery` 与隐私锁。
3. 浏览器只能读取本人来源与运行记录；提出来源和执行运行仅允许 service role，公开 RPC 均为 invoker 薄包装。
4. 每次运行使用来源级幂等键，并记录成功、部分、失败或取消。部分/失败必须给出覆盖缺口，权限在提交前失效时改记为安全取消。
5. V0 首切片不抓取真实网站、不创建候选、不评分，也不接入受限平台登录。真实适配器与候选投影必须等 D14-D16 确认后另行验收。

## 后果

- 状态中心可以诚实区分未配置、待审批、停用、等待首次核验、健康、部分、失败和过期。
- 来源选择仍由用户决定；控制面上线不会产生外部访问。
- 后续适配器必须复用相同的审批、频率、运行和健康边界，不能绕过来源注册表直接写候选。

## 验证

- 隔离 Test 回滚事务验证默认关闭、审批不隐式启用、权限门、运行幂等、部分覆盖、RPC 权限矩阵和候选零变化。
- RLS、显式 Data API 授权、外键索引、Advisor 与全量 CI 均通过；合成来源、运行和游标残留为 0。

## 后续状态（2026-08-26）

- D14-D16 已确认；首个真实适配器 Goldman Sachs APAC Early Careers 复用本 ADR 的来源注册、审批、频率、运行健康和提交前权限门。
- 用户批准每 6 小时频率不隐式启用来源。隔离 Test 中该来源保持 `approved / disabled`，因为 `job_radar.discovery` 临时授权已经过期。
- 适配器只访问 `www.goldmansachs.com` 的固定公开学生项目页；robots 禁止的 Campus 入口不访问。官网缺少部门、地点或工作资格证据时记录 partial 覆盖缺口，不推断为完整岗位。
- 真实投影在回滚事务内验证首次创建 2 条候选、重复运行 0 条新增；事务后候选、运行、条目和游标仍为 0，Production 尚未部署。
