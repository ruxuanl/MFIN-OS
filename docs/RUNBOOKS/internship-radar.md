# 手动实习发现雷达（#48）

用户授权来源：2026-11-14 本次任务；D14、D15 的已确认方向及资格核验边界继续有效。用户明确改为跨网站搜索，#21/#22 继续搁置；没有启用定时任务。

## 使用

本地运行后，在实习页点击“发现实习”，或打开 `/internships/discover`。默认条件来自项目已确认背景，可修改；本人必须勾选确认画像。搜索条件只填写岗位、地区、类型，不填写联系方式。搜索商不会收到画像；AI 只收到简短确认画像和有界岗位证据，不读取任何简历。

在状态中心的能力注册表开启岗位发现（持续或限时）。AI 理由另需雷达评分、AI 总开关及已有 JD 分析权限；没有 AI 权限、预算或服务时保留真实搜索结果。隐私锁阻止外部请求与候选写入。首版不支持绑定 operation ID 的“仅本次”发现授权，界面明确要求限时或持续。

Tavily 的 `TAVILY_API_KEY` 仅存服务器环境，本地为被忽略的 `apps/web/.env.local`。不要使用 NEXT_PUBLIC 前缀。每次只调用一次 Basic Search，最多 8 条、25 秒超时、零重试；每用户 60 秒冷却、运行租约 3 分钟，滚动 24 小时最多 20 次。每次尝试均占用一次本地限额，避免上游计费不确定时反复请求。AI 最多一次，40 秒超时、1800 输出 tokens，复用现有跨提供商 HK$100 月预算；无法确定计费的 AI 请求保留预留。

选择 Tavily 是因同一次请求能取搜索结果和页面文本，Basic 搜索为 1 credit；[官方额度说明](https://docs.tavily.com/documentation/api-credits) 提供免费额度。Exa 也支持搜索时取文本，参见 [Exa Search](https://exa.ai/docs/reference/search)。两家对香港金融实习的实际召回率没有完成配对对照，不能声称哪家覆盖更好。禁止为此购买套餐或开启付费超额消费。

## 数据和证据

新增 private.radar_runs/results，客户端无表访问权限；所有本人读写经 invoker 公共包装与检查 auth.uid 的 private 函数。只有 service role 能提交搜索结果与结算已知实际 AI 消耗。来源文本是不可信数据，不能作为模型指令。所有文本均按纯文本渲染。

搜索结果永远先进入发现暂存区。点击“加入候选”才写现有 opportunity_candidates；未知公司可在确认前修正。忽略只更新发现结果。同一用户按规范化 URL 去重，去掉片段和常见追踪参数，保留岗位路径及 jobId 等查询参数。不同公司域名或不同 requisition 不会按公司名称误合并；跨域镜像仍可能重复，需要人工判断。并发确认在数据库串行化，重复返回既有候选。

原文未明确出现的公司、地点不猜测；从页面文本尝试提取明确截止日期，缺失显示未知。匹配岗位 URL 与标题模式只标记“疑似具体岗位页”，不能作为已核实开放。关闭证据或已过明确截止日期的结果标记关闭、禁止加入。其他列表/文章/类型不明结果明确标注待核实。首版没有任何未经人工核对的“已核实”开放状态。搜索索引可能滞后；保留可打开的来源与发现时间。同 URL 再次出现不覆盖原始发现证据或已加入/忽略决定，首版展示最近 40 个发现结果。

## 验证与发布

运行 `pnpm run ci`，数据库验证脚本为 `tests/db/manual-search-radar.sql`：仅用户自己的单用户隔离 Test，全事务回滚；覆盖未登录、角色授权、用户隔离、并发冷却、确认去重、忽略、隐私锁与权限关闭。该事务测试不能代替真实搜索和页面持久化验收。

新增迁移 `manual_search_radar` 只能增量应用。AI 依赖本机已有但此前未提交的 D35 DeepSeek 配置与 provider accounting 迁移；这些不属于 #48 增量，发布必须先审阅依赖并确保目标已应用。不得重新 bootstrap 现有库。

部署前确认准确 Vercel team/project/environment 和对应 Supabase；检查服务端 Tavily/DeepSeek 配置、迁移、Google/Supabase 登录回调。未确认目标前不部署任何 Production；本地运行不代表公网已上线。演示：真实登录 → 确认条件 → 发现 → 打开具体来源核验 → 加入候选 → 打开候选池并刷新 → 同一结果再次确认不重复；另一结果忽略后不入候选。
