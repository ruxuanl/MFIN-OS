# 材料工作区：上传、版本删除与排版分析

2026-11-15：用户确认电脑端浅色、留白、深绿点缀。上传区先选文件，自动取文件名，可编辑材料名称；归入已有材料后名称/类型固定，版本关联折叠。版本库保留紧凑元信息、打开文件、分析与删除操作；评分与建议折叠。样式只作用于材料页，不扩展手机设计。

## 排版分析

DeepSeek Flash通过Responses API接收本地渲染的PDF页面图（最多前3页，1600像素长边），结合正文给排版、内容、清晰度、ATS与总分。图片仅内存传递，原始PDF不作为DeepSeek文件上传；请求store=false、无重试，沿用已有权限与HK$100共享月预算。`resume_analysis_v2_visual`使旧的纯文字缓存不再冒充视觉结果；现有简历需点“更新分析（含排版）”，新上传沿用自动分析。

DOCX的排版分基于文档格式属性，标注`structure_and_content`；没有最终页面渲染，不声称已评估视觉溢出或精确对齐。PDF标`visual_and_content`并说明抽样范围。DeepSeek V4 Pro不支持本路径图片输入，当前限定Flash。Python3环境安装`py -3 -m pip install -r scripts/requirements-resume-visual.txt`，当前本机已具备PyMuPDF。

## 删除一个版本

本人在确认框核对影响后删除；要求近10分钟重新登录。过期时材料页提供Google重新登录入口，回来需再次确认。服务端RPC在隔离Test运行，检查本人归属、隐私锁和新近登录，事务内清除该版本、私有正文/技能关联、AI分析及由其产生的申请草稿、岗位简历关联、申请包推荐/选择；历史投递记录仅清空简历引用和标签，岗位、投递状态及费用审计保留。其他独立版本保留，派生版本的来源关联置空。

本地面试引擎清除使用该版本的练习及PDF；Storage SDK删除原件。跨存储步骤失败时保留`private.resume_deletion_jobs`待办，版本先不可选，页面可重试清理。主应用每次面试请求同步已删版本ID，防止正常打开旧记录恢复已删资料；浏览器不可直接调用内部purge命令。完成标记不代替Storage删除，只有服务端实际清理成功后标记。未代用户删除真实版本。
